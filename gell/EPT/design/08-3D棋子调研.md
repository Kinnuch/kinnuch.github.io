# 08 · 3D 棋子可行性调研（M5 预研）

> 2026-08-06 · 结论：**可行且已跑通概念验证**。推荐"战斗 3D 化、备战保持 DOM"的渐进方案，等待拍板后立项 M5。
> 概念验证页：`model-test.html`（本地起服务后打开即可看到 3 个模型在六边形地格上播放动画）。

## 一、结论先行

| 问题 | 答案 |
|---|---|
| 能不能在纯静态 GitHub Pages、无构建步骤下渲染 3D 棋子 | ✅ 能。three.js 以 ES Module + importmap 直接 vendor，PoC 已在项目内跑通 |
| 有没有授权干净、风格统一、带动画的免费模型 | ✅ KayKit（CC0，可商用免署名）低多边形角色包，自带 **76 个动画**（待机/走/跑/受击/死亡/施法/各类武器攻击/欢呼），且有 25+ 武器配件可自由挂载 |
| 体积会不会失控 | ✅ 实测单角色 3.5MB → 裁剪到 13 个战斗动画 + quantize = 2.26MB → 叠加 meshopt 压缩 = **0.56MB**。10 个原型全套约 5~6MB，按需懒加载 |
| 兼容性 | three.js 支持所有现代浏览器；无 WebGL 时可回退现有 2D DOM 渲染。无头 SwiftShader 下也能渲染（自动化截图测试可用） |

## 二、路线对比

| 路线 | 说明 | 判定 |
|---|---|---|
| **A. three.js 单场景层**（推荐） | 一个 WebGL canvas 叠在棋盘区域，战斗回放事件驱动模型动画；UI 面板/血条仍是 DOM | ✅ PoC 已验证 |
| B. `<model-viewer>` 每棋子一个组件 | 每个组件一个 WebGL context，浏览器上限 8~16 个，棋盘 18+ 单位必炸 | ❌ 不可行 |
| C. 模型离线渲染成精灵图 | 本质还是图片，不是用户要的"建模"；且需要离线渲染管线 | ❌ 不采纳 |

## 五、事件 → 动画映射（引擎无需改动）

战斗回放事件流完全够用，**引擎零改动**，只换渲染层：

| 回放事件 | 动画 |
|---|---|
| spawn | Idle |
| move | Walking_A（速度快时 Running_A） |
| atk | 1H/2H_Melee_Attack_* 或 *_Ranged_Shoot（按职业配置） |
| cast | Spellcast_Shoot / Spellcast_Raise |
| dmg（大额） | Hit_A |
| die | Death_A（尸体保留数秒后下沉消失） |
| end（胜方） | Cheer |

裁剪保留清单（13 个）：Idle, Walking_A, Running_A, Hit_A, Death_A, Cheer, Spellcast_Shoot, Spellcast_Raise, 1H_Melee_Attack_Slice_Diagonal, 2H_Melee_Attack_Chop, 1H_Ranged_Shoot, 2H_Ranged_Shoot, Block。

## 六、体积实测（Knight，含全部配件网格）

| 处理 | 体积 |
|---|---|
| 原始 glb（76 动画） | 3.49 MB |
| 裁到 13 动画 + resample + quantize | 2.28 MB |
| + EXT_meshopt_compression | **0.56 MB** |

处理管线：`@gltf-transform/core/functions/extensions` + `meshoptimizer`（离线一次性，产物提交仓库，运行时无需构建）。
预算：three 670KB + 解码器 48KB + 10 原型 ×0.6MB ≈ **6.5MB**，全部懒加载（进战斗才拉当场需要的原型，首屏零增量）。

## 七、集成方案（M5 提案）

**渐进式：战斗 3D、备战 DOM**（推荐）
- 备战阶段完全不动：拖拽、点击、面板、商店全是现有 DOM 逻辑，零回归风险。
- 开战后把 `#board` 内的 DOM 棋子层换成 three.js canvas：回放事件驱动 mixer；血条/法条/护盾/状态标记仍用 DOM overlay（把 3D 坐标投影到屏幕坐标，每帧同步位置——与现有 updateBars 完全复用）。
- 相机固定复刻现 2.5D 视角（PoC 已校准 38°），滚轮缩放映射到相机距离；"视角"按钮在 3D 下切换俯视/斜视。
- WebGL 创建失败（极老设备）→ 自动回退现有 2D 渲染，代码路径保留。

**激进式：全程 3D**（备选）：备战也在 3D 场景里拖拽（raycaster 拾取），沉浸感更强，但拖拽/商店/合成交互全要重写，工作量 ×2.5，风险高，不推荐首版。

2. **大体型单位**：✅ 已找到 Quaternius 两个 CC0 包并验证渲染通过（见九）。

## 十、M5 实装拆解（全程 3D 版）

1. **管线脚本**（离线，一次性）：全部原型 trim 动画 → quantize → meshopt → `assets/models/packed/*.glb`（含猎人配件挂载预处理）；产物提交，PoC 原始文件删除。
2. **board3d.js 渲染层**：场景/相机（复刻 38° + 滚轮缩放）/灯光/六边形棋盘网格；单位管理（spawn/despawn/tint/星级底座/朝向）；DOM overlay（血条法条状态标记投影跟随）。
3. **备战交互**：raycaster 拾取拖拽（棋盘内换位/上下场）、DOM 备战席 ⇄ 3D 棋盘跨界拖放、点击弹面板、悬浮高亮；沿用现有 dispatch 动作层，引擎零改动。
4. **战斗回放**：事件→动画状态机（第五节映射表）、移动插值、投射物与技能特效迁移到 3D（或首版保留 DOM 特效层叠加）。
5. **回退**：WebGL 创建失败自动回退现有 2D DOM 渲染（代码路径保留，`?2d=1` 强制）。
6. **兼容与性能**：Firefox/Edge 实测、手机端测试、18 单位同屏帧率验证。

M5 ≈ 一个完整里程碑：模型处理管线脚本（0.5 天）→ 战斗渲染层重写 + 事件-动画状态机（2 天）→ DOM overlay 投影同步（0.5 天）→ 10 原型配置/配件/染色（1 天）→ 回退路径与兼容测试（0.5 天）。
