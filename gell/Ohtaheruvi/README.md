# Ohtaheruvi · 中土战争领主

以《精灵宝钻》为舞台的网页 2D 回合制战略。规则骨架取自 1989 年 Steve Fawkner 的 *Warlords*
（及其 2012 年的 iPad 移植版 *Warlords Classic HD*），世界观、势力、英雄、兵种全部替换为中土设定。

纯前端，无构建步骤、无框架、无依赖。直接打开 `index.html` 即可（需通过 HTTP 访问，ES Module 不能走 `file://`）。

## 目录

```
index.html          入口
css/ohta.css        主题与面板样式（复用站点的 data-theme 深色切换）
js/                 rng 随机 · map 地形与寻路 · unit 单位读取器 · combat 战斗 · fog 战争迷雾
                    state 对局状态与规则 · scenario 场景层 · ai 三层 AI
                    commands 指令层（单人与联机共用）· net 联机传输（PeerJS）
                    render Canvas 绘制 · tiles 地形自动拼接 · portraits 程序化肖像 · sound 合成音效
                    ui 界面 · chart 统计曲线 · tutorial 新手教程 · save 存读档 · main 启动与输入
data/               units 兵种表 · heroes 英雄名录 · items 神器 · factions 势力 · terrain 地形
                    era3 第三纪元的势力/兵种/英雄/神器（合并进上面各表）
maps/               beleriand.js / northwest.js 地形层（均为生成物，勿手改）
                    scenarios.js 第一纪元战役 · scenarios-t3.js 第三纪元战役 · test.js 小测试图
tools/              paint.mjs 地形绘制原语 · gen-beleriand.mjs / gen-northwest.mjs 地图生成器
                    （构建时跑一次，运行时不加载）
design/             中文设计文档（00 总纲含【待裁决】清单）
test/               smoke.js 无头规则测试（81 项）· lockstep.js 联机同步测试
                    browser.html 浏览器端集成测试（65 项）· perf.html 渲染性能测量
```

## 测试

```sh
node test/smoke.js                 # 规则内核，不碰 DOM
node test/lockstep.js              # 联机同步：同一串指令在两端必须推演出同一个局面
python -m http.server 8000         # 然后浏览器打开 test/browser.html，看页面底部结果
```

```sh
node tools/gen-beleriand.mjs       # 改了地理描述后重新生成贝烈瑞安德
node tools/gen-northwest.mjs       # 同上，中洲西北
```

`?seed=12345&sc=dagor_bragollach` 可直接开指定战役并复现同一局（同种子必定产生完全相同的对局）。

## 当前进度

**M1 · 引擎骨架（已完成）**：地形渲染与八向寻路、八单位军团堆叠与分队、逐次决斗的战斗结算与战前胜率预估、
城市生产与投送、收支与破产解散、遗迹／祭坛／先知、英雄求聘与神器掉落拾取、胜负判定、存读档、
一张 40×30 测试地图。

**M1.5 · 首轮反馈（已完成）**：
- **移动撤回**（左上角按钮 / `Ctrl+Z`）：可连续撤回本回合的多步移动；一旦交战或探索遗迹，撤回栈立即清空，避免变成读档大法
- **统计曲线**（`G` 键）：按回合画出各方金币、城池数、部队数三张小多图，含悬停十字准星、线端直接标注与表格视图
- **新手教程**：十步分步引导 + 界面高亮，首次游玩自动打开，可随时跳过或从顶栏重开
- **地块面板**：点任意一格显示地形、移动消耗、通行限制、城市数据、地物状态，以及哪些兵种在该格防守时有地形亲和
- **生产卡片**：取代下拉框，每排两张，摊开强度／耐久／移动／造价／维护／建造回合与特性标签
- **AI 执棋**（原定 M3，为此提前实现简化版）：AI 各方在你结束回合后自动走完，直接轮回你，画面中央渐隐提示新回合
- 行动条改为金色（绿色会被误读成血量，耐久才用绿）

**M2 · 内容与贝烈瑞安德全图（已完成）**：
- **场景层**：地形层（`maps/beleriand.js`）只描述地理，战役配置（`maps/scenarios.js`）描述「这一战」——谁参战、城归谁、开局带什么兵、开放哪片区域、怎样算赢、第几回合触发什么。新增一场战役不用重画地图。
- **贝烈瑞安德全图 140×110，49 座城、22 处地物**，由 `tools/gen-beleriand.mjs` 按地理描述生成（山脉、河流、渡口、道路、森林一次画成，带落点校验与自愈）。刚多林的环形山谷、西瑞安河的四处渡口、安德拉姆长墙、欧西瑞安德七河都在图上。
- **三场战役**：自由征服（八方混战）、星下之战（费艾诺 vs 安格班，含「追得太深就撞上炎魔」的正典抉择）、骤火之战（开局把阿德加兰烧成安佛格砾斯的焦土，格劳龙与炎魔倾巢而出）。
- 大厅改为战役选择 + 执掌方选择；存档记录战役 id，读档自动还原对应地图。

**M3 · 内容完整（已完成）**：
- **战争迷雾** 三档：全知 / 记忆制（默认，走过的地形与城市归属永久保留，敌军只在视野内可见）/ 严格迷雾。已探索区域按位打包 + base64 存档，一方约 2.6KB。
- **AI 三层**：战略层（威胁评估、前线/腹地标签、金币分配）→ 战役层（DEFEND / ATTACK / EXPLORE / MERGE / SCOUT 任务分派）→ 战术层（跨回合路线推进、胜率阈值决定打或等）。
- **四档难度** 仁慈 / 正常 / 困难 / 魔苟斯，差别落在「愿意为目标跑多远、攻坚前攒多少兵、留守比例、派多少斥候」上。前三档同样受迷雾限制，只有魔苟斯档全知且在难度说明里写明——**数值上一律不作弊**。
- **十场战役**：第一纪元七场（自由征服、贝烈瑞安德第一战、星下之战、荣耀之战、骤火之战、泪雨之战、愤怒之战），第三纪元三场（中洲自由征服、魔戒战争、北方战争）。
- **中洲西北全图 160×120，40 座城**，由 `tools/gen-northwest.mjs` 生成：迷雾山脉、安都因大河与五处渡口、三面环山只有黑门与西力斯乌苟两个入口的魔多、幽暗密林与孤山。
- **第三纪元内容**：26 个兵种、34 名英雄、11 件神器（`data/era3.js`），势力编号 11~18 与第一纪元分开。
- **魔戒战争的双胜利路径**：正面打赢，或派英雄带着至尊魔戒抵达末日火山——但戒指每回合都在腐蚀持有者，腐化满了他会带着戒指叛投魔多。
- **战史面板**（`H` 键）：最近 60 场战斗，点开看完整的逐次决斗记录。

**M4 · 美术与打磨（已完成）**：
- **地形自动拼接**：地貌不再是一格一格的方块。先铺一层「地」，再把森林、山地、水面等按 8 邻位掩码画成**有机色块**——四条边与同类邻格相连时顶到格子边界，四个角两侧都相连就是直角、否则倒圆角，相邻同类格因此连成一整片。只描外沿，色块内部没有接缝。
- **笔触装饰**：针叶树有受光面与投影、山峰有阴阳面与雪顶、麦垄、芦苇、波纹、碎石——位置与大小由格子坐标做确定性哈希，同一张图每次画出来都一样。
- **程序化肖像**：54 个兵种按族裔与兵种类型选原型（头盔／弓／马首／龙头／炎魔角／骷髅／船帆／翼／兽首），套上各自色板画成圆形剪影，按「类型+尺寸」缓存。地图徽章、军团队列、生产卡片共用同一套。
- **战斗动画**：两侧肖像在目标格上方对冲，命中时抖动、熄灭一颗耐久点、迸出火花。胜负早在 `combat.js` 里算完，动画只是把它演出来。
- **音效**：全部用 WebAudio 现场合成（移动、交击、阵亡、占城、回合、胜负、拾宝），**不加载任何音频文件**。
- **分块离屏缓存**：地形按 16×16 格烘到离屏画布，只在缩放或地形变化（焦土化、沉没）时重烘。160×120 满编 233 单位实测：首帧 41ms（烘块），稳态帧的绘制命令提交低于 0.1ms。
- **触屏**：iPad 上支持双指缩放（吸附到缩放档位）。

**全部美术为程序化绘制，仓库里没有一个二进制素材** —— 既守住了「不得使用原作素材」的版权红线，也让体积远低于 6MB 的上限。

**M5 · 联机（已完成）**：
- **指令层**（`js/commands.js`）：玩家的每一个操作都变成一条可序列化、可重放的指令。**单人模式走的也是这条路径**，只是指令产生后立即本地执行——两种模式共用同一套代码，才不会出现「只有联机才有的 bug」。
- **房主定序 + 各端重放**（`js/net.js`，PeerJS 点对点，本地 vendor 无 CDN）：客户端把操作发给房主，房主赋序号后广播（含发回自己），各端严格按序号应用。**网上只传指令，不传局面**——随机数是种子化的、AI 是确定性的，同一串指令各端推演出同一个局面。
- **失步检测与重同步**：房主每条指令都带上自己的局面指纹，客户端一比对就知道有没有分叉；分叉了就向房主要一份完整存档重来。
- 2~8 人，空出来的势力由 AI 接管；只有轮到你时才能操作。
