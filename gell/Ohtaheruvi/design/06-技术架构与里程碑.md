## 二、核心数据结构

```js
// 单位实例
{ id, type:'noldor_sword', owner:2, hp:2, maxHp:2, mp:8, blessed:false, cargo:null }

// 军团（格上的堆叠，最多 8）
{ x, y, units:[...], heroId:null|id, order:'asc'|'desc' }

// 城市
{ id, x, y, name, size, owner, defense, produces:[type...],
  building:{type, turnsLeft}, vectorTo:null|cityId, razed:false }

// 英雄
{ id, name, faction, strength, mp, items:[itemId...], alive:true, x, y }

// 对局状态
{ seed, turn, current, scenario, fog, factions:[...], armies:[...], cities:[...], heroes:[...], log:[...] }
```

- **全部随机走 `rng.js` 的种子化发生器**，不用 `Math.random()`。这让「同一存档重放出同一结果」成立，也让 bug 可复现、战报可回看。
- 存档 = `JSON.stringify(state)`（地形不存，从 map JSON 重建）。一局约 80~200 KB，`localStorage` 完全够。

## 三、AI 设计

> **已实现**（M3）：三层与四档难度都已落地，见 `js/ai.js`。
> 实测每个 AI 回合：小图 3ms、贝烈瑞安德 17~29ms、中洲西北 52ms，均远在 1500ms 预算内。
>
> 一条实测得出的教训：**四档难度真正的差别不在「进攻胜率阈值」上**——那个阈值只在目标有守军时才生效，
> 单独调它三档跑出来一模一样。真正决定局势的是三件事：愿意为一个目标跑多远（`targetRange`）、
> 打有主之城前肯攒多少兵（`minStack`）、以及**派多少斥候去探图**（`scoutRatio`）。
> 开了迷雾之后，限制 AI 扩张的头号因素其实是它「看见了多少」，不是它多敢打。

三层，逐层降级以保证 1.5 秒预算：

1. **战略层**（每回合一次）：评估各势力威胁值、给己方每座城市打「前线/腹地」标签、决定金币分配（扩军 / 攒钱雇英雄 / 升级防御）。
2. **战役层**：把军团分派任务——`DEFEND(城)` / `ATTACK(城)` / `EXPLORE(遗迹)` / `ESCORT(英雄)` / `MERGE(合流)`。目标选择用「价值 / 距离 / 预估胜率」的评分，预估胜率直接复用 `combat.js` 的蒙特卡洛（次数降到 200 次）。
3. **战术层**：每个军团用 A* 走向目标，交战前用胜率阈值决定打还是等援军（默认阈值 55%，难度越高阈值越贴近最优）。

**难度四档**：仁慈 / 正常 / 困难 / 魔苟斯。差异体现在目标搜索半径、攻坚前的集结门槛、留守比例、斥候比例，以及是否受迷雾限制（前三档受限，「魔苟斯」档全知且在难度说明里对玩家写明）——**不给 AI 任何数值作弊**，这条守住了。

## 四·五、联机（M5 实装记录）

**同步模型**：房主定序 + 各端重放。客户端把操作发给房主，房主赋序号后广播（含发回自己），
各端严格按序号应用。网上只传指令，不传局面。

**为什么可行**：随机数全部走种子化发生器（`rng.js`），AI 是确定性的，
场景脚本也只依赖对局状态——同一串指令在每一端推演出同一个局面。

**做这件事时挖出来的三个真实隐患**（都写了回归测试）：

1. **AI 的时间预算**。原来是「每个 AI 回合最多跑 1500ms」，快的机器多走几支军团、
   慢的少走几支，局面立刻分叉。改成固定的动作上限（400 支），实测最大的图一回合也就 52ms，够用。
2. **单位编号是模块级全局计数器**。同一个页面里开过第二局的人，其单位编号会接着上一局往下数，
   而刚进来的人从 1 开始——指令里引用的 uid 就会指错单位。改为挂在对局上（`G.nextUid`）。
3. **剧本事件的「已触发」标记打在场景对象上**。场景定义是所有对局共享的模块级常量，
   一端触发后另一端就以为剧本已经发生过了。改为记在对局上（`G.firedEvents`），并纳入存档。

前两条在单机下几乎不会暴露，第三条会让「同一标签页里开第二局时剧本不触发」——
都是联机把它们逼出来的。

**失步兜底**：房主每条指令都附带自己的局面指纹（`checksum()`，只取真正决定局面的字段）。
客户端一比对就知道有没有分叉，分叉了就向房主要一份完整存档重来。

**单人也走同一条路**：`ui.dispatch → submit → applyCmd`。界面层绝不直接改状态。
这样联机路径每天都在被单人模式跑，不会烂掉。
